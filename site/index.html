Flight recorder

A rolling five-minute buffer, always on, never started

On the sites you choose, TestLens continuously keeps the recent past and discards the rest. Nothing leaves the browser.

  • Console & errors including stack traces, unhandled rejections and CSP violations
  • Every request with headers, status and timing; bodies for your app's API calls
  • Clicks, inputs and route changes, values masked
  • DOM replay plus a screenshot at the moment you report
  • Video of the current tab, or the entire window with your microphone, stitched into one file

Proactive alerts

TestLens notices the failure before you do

A 500, a connection error or an uncaught JavaScript error in a monitored tab turns the toolbar badge red and shows a small toast with a one-click report. Rate-limited, mutable per tab, and the threshold is yours (500+, or 400+).

  • Toast button preserves evidence instantly
  • Shortcut Alt+Shift+R reports with a full screenshot
  • Popup pulses with the count of failures seen

Evidence engine

Hundreds of events in, the few that matter out

A deterministic engine scores the failure most likely to be the cause, then pulls in what relates to it: shared correlation IDs, the click two seconds before, the same endpoint succeeding earlier, the console error that followed. Every selection shows its reason, and you can override the focal event.

  • Redaction first: tokens, cookies, passwords, card numbers, JWTs masked before anything is stored or sent
  • Full request detail with correlation IDs highlighted, cURL to reproduce, backend trace links
  • Rewind to failure: markers on the video jump to each failed request
  • Markup: boxes, arrows, text and pixelate on the screenshot

AI, kept honest

Suggestions beside the facts, never instead of them

An AI model rewrites the steps to reproduce from your recorded actions and drafts the summary, expected and actual result. It sees only a redacted projection, never headers, cookies, screenshots or video. Nothing is applied until you click.

  • Zero setup by default: Chrome's built-in on-device model, nothing leaves the machine
  • Free tiers: Groq, Gemini, OpenRouter; or Ollama locally; or OpenAI
  • Applied text is badged AI in the panel and in the issue description

API testing

Postman, Newman and HAR files flow through the same lens

A small local Hub receives evidence from API tools and normalises it. The extension pulls those incidents and handles review, AI and tracker creation exactly like browser bugs. No tracker credentials live in the Hub.

  • Postman: paste one snippet into the collection; it reports only on failures
  • Newman: a reporter for CLI and CI runs
  • HAR from DevTools, Charles, Fiddler or Proxyman: import directly, no Hub needed

Settings map

Configure once per browser

Settings sync with your Chrome profile, apply to every window including Incognito once allowed, and can be exported as a token-free file for the team. Nine sections, each with a default that works.

1 · Monitored sites

Domain-wide entries; edit in place; app names; environment label.

default: none until you add your app

2 · Capture

Rolling window, post-click window, body size, replay, input masking, video auto-start, default attachments.

default: 5 min · 15 s · 256 KB

3 · Bug tracker

Pick a tool, get a token in one click, connect, choose project and type, required fields as dropdowns.

default: Jira Cloud

4 · AI analysis

Provider, model, what is sent, auto-run.

default: Chrome built-in, on-device

5 · API testing tools

Hub URL, auto-pull, Postman snippet.

default: off

6 · Failure alerts

Badge, toast, status threshold, JavaScript and network errors, cooldown.

default: on · 500+ · 20 s

7 · Redaction

Built-in rules always on; add your own keys and regexes.

default: tokens, cookies, cards, JWTs…

8 · Trace links & noise

Deep links from correlation IDs into your logging tool; extra telemetry hosts to ignore.

default: none

9 · Data

Retention, clear local data, reset.

default: 7 days
